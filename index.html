这个看板帮你发现值得进一步核价的低价行程。它展示的是筛选后的候选，并非所有航班，也不保证覆盖全网最低价。

查询失败后，怎样获取更新结果？

刷新网页只会读取已经发布的报价，不会重新搜索机票。要再查一次，请点击页面顶部的“重新查询 ↗”：

  1. 进入 GitHub 后，登录拥有此采集仓库权限的账号。
  2. 点击 Run workflow，分支保留 main。“仅测试四城到吉隆坡”保持不勾选，即查询全部国家。
  3. 点击表单中的 Run workflow 启动。若已有任务运行，新任务会排队。
  4. 采集通常需要几分钟；任务最长约 20 分钟，排队时间另计。保存和发布完成后，回到看板刷新，并检查顶部的查询更新时间是否变化。
打开 GitHub，重新采集 ↗

重新采集会再查全部配置范围，不只是失败航线。网络波动可能重试后恢复；来源限制、页面变化或无有效结果不保证能靠重试解决，避免连续重复启动。若只想核对某条已有报价，可在“查看详情”中打开来源页面重新查价。

航班从哪里来？查询哪些地方？

自动来源为 Google Flights 的网页数据，不是承诺稳定的官方免费 API。目前没有自动接入携程、去哪儿或各航司官网，也不代表各平台都已比较。

查询范围随看板配置更新；请参见出发城市、目的国家与机场筛选。

    统一条件：1 位成人、经济舱、直飞、来源以人民币展示的价格，包含来源显示的必付税费。行李和退改条件待确认；不含前往出发机场的地面交通费用。起降时间使用机场当地时间，查询时间使用北京时间。

    为什么只显示部分航班？怎样选出来的？

    1. 先扫描单程日期价格。对配置内的每条航线查询未来窗口的每日最低参考价，作为候选日期线索；它不是全部航班的清单。
    2. 再核对低价候选。当前默认每次采集最多查询 48 组“航线＋出发日期”。先为每个“出发城市＋国家”选一个有报价的低价日期，再优先覆盖不同航线，剩余名额按低价填充。每组最多保留 5 条符合条件的低价航班结果。
    3. 往返单独核价。每个国家优先选 2 条低价航线，比较停留 5／7／10 天的方案，再选最多 3 个候选行程查询真实整程报价。日历不可用时，以单程低价日期试查往返。每个候选只展开一个低价去程选项，最多保留 5 个整程结果，不穷举所有去回程组合，也不把两个最低单程价相加。

    这些是程序设置的工作量上限，不是平台提供的收费查询额度。运行时限、访问限制或查询失败会减少实际完成量；“未列出”不代表没有航班。

    页面怎样排序？“最低价”指什么？

    默认先显示本次取得、且查询时间未超过 26 小时的报价，再按价格从低到高排列；历史报价排在后面。也可切换为出发日期或最近查询排序。每页 15 条，可以翻页，并按城市、国家、机场、月份及单程／往返筛选。

    顶部最低价仅来自当前筛选下的本次有效航班报价，历史报价不参与。“价格日历”显示当前筛选下每个出发日期的最低参考价，尚未逐日核对所有具体航班。来源显示价不等于商家最终结算价，购买前需要重新确认。

    更新记录里的状态分别是什么意思？

    完成
    该项查询取得了有效报价。
    本次无报价
    来源本次未返回符合筛选条件的结果，不等于没有航班。
    查询失败
    未取得可靠结果，可能是网络、来源限制或返回格式异常；保留对应旧报价及原查询时间。
    本次未查询
    达到运行时限，或触发连续失败／访问限制保护，留待下次查询。

    “部分查询未完成”表示部分项目失败或未查询，其他成功项目仍可查看。某国往返日历失败，也可能已经取得该国的具体往返航班报价；两种查询分别展示。

    历史价格与 Excel 会保留吗？

    每次采集记录保存在你的 GitHub 私有仓库。看板仅展示当前出行窗口内的行程；点击报价详情，可查看同一报价最近最多 60 次观察。过了出发日期的记录会从看板移除，私有历史仍保留。

    “下载 Excel”导出最近发布的报价快照及查询时间，适合筛选和保存，并非全部历史档案。历史仅从本系统开始采集时算起，不能据此声称某价格是全年最低。
